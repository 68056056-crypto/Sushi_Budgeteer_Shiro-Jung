# Data dictionary และ provenance

`CSV → import validation → SQLite` โดยตาราง `menu` มี primary key `item_id` และ `metadata` เก็บชื่อไฟล์ SHA256 วันที่ import และลิงก์เกณฑ์ allergen ที่ผู้ใช้ให้ dataset ปัจจุบันมี 42 รายการ (B005 น้ำเปล่า 20 บาท เพิ่มตามราคาที่ผู้ใช้แจ้ง สถานะ unverified) ไม่มี secret หรือประวัติสนทนาในฐานข้อมูล

| คอลัมน์ | ความหมาย |
|---|---|
| item_id | ID ไม่ซ้ำและไม่ว่าง |
| name_th / name_en | ชื่อไทย/อังกฤษ |
| category / plate_color | หมวดอาหาร/สีจานจาก dataset |
| price_baht | ราคาหน่วยบาท ไม่ติดลบ ทศนิยมสูงสุด 2 ตำแหน่ง |
| description_th / keywords | คำบรรยาย/คำค้น; keywords คั่นด้วย `;` |
| allergen_tags | แท็กสารก่อภูมิแพ้คั่นด้วย `;` จาก dataset ไม่ได้แปลว่าร้านยืนยันแล้ว; CSV รุ่นเก่า `allergens_verified` ยัง import ได้ |
| dietary_tags | แท็กอาหารแบบ exact เช่น raw, cooked, pork, chicken; ใช้กับข้อห้ามแทน fuzzy matching |
| dietary_status | reviewed_dataset = ทบทวนตามคำบรรยายชุดข้อมูลเพื่อการศึกษา ไม่ใช่หลักฐานส่วนผสมจากร้าน |
| source_url | แหล่งอ้างอิงเมนู/ราคา; ชุดข้อมูลที่แนบเว้นว่าง เพราะยังไม่ได้ยืนยันแหล่งข้อมูลรายเมนู |
| price_status | confirmed หรือ unverified; ชุดที่แนบเป็น unverified |
| allergen_review_reason | เหตุผล/แหล่งข้อมูลที่ทีมตรวจรายเมนู; จำเป็นเมื่อ team_reviewed ไม่ใช่ร้านยืนยัน |
| allergen_reviewed_by | ผู้ตรวจจริง; จำเป็นเมื่อ team_reviewed พร้อม checked_at |
| allergen_status | confirmed, team_reviewed หรือ unknown; ชุดที่แนบยังเป็น unknown ทั้ง 42 รายการ |
| allergen_source_url | หลักฐานส่วนผสม/สารก่อภูมิแพ้ของเมนูจากร้าน/ผู้ผลิต ไม่ใช่แค่เอกสารกฎหมายทั่วไป |
| checked_at | วันที่ตรวจหลักฐาน เช่น ISO 8601; เว้นว่างเมื่อยังไม่ตรวจ |

Importer อนุญาต `confirmed` เมื่อมี metadata ที่จำเป็น แต่ไม่สามารถรับรองความน่าเชื่อถือของ URL/ผู้กรอกเองได้ ต้องมีผู้รับผิดชอบตรวจต้นฉบับก่อนตั้งสถานะนั้น อย่าใช้ข้อมูล fixture จาก tests เป็นหลักฐานของร้าน

Vocabulary ปัจจุบันรองรับ `fish`, `crustacean`, `molluscs`, `echinoderm`, `egg`, `milk`, `gluten`, `soy`, `sesame`, `pork`, `seafood`, `peanut`, `tree_nuts`, `sulphites` เป็นศัพท์ของแอป ยังไม่อ้างว่าตรงรายชื่อ/ขอบเขตตามกฎหมาย อย. ทุกข้อ `pork` เป็นข้อจำกัดอาหารที่อาจใช้ในแอป ไม่ได้อ้างว่าเป็นสารก่อภูมิแพ้ที่กฎหมายกำหนด หาก extractor ส่งชื่อที่ไม่รู้จัก จะคงชื่อไว้และ strict mode ปิดกั้นเมื่อไม่มีหลักฐานเพียงพอ ต้องถาม/ตรวจเพิ่ม ไม่ทิ้งข้อมูลเงียบ ๆ

ข้อมูลว่างไม่ได้หมายถึงปลอดสารก่อภูมิแพ้ การรับรองต้องครอบคลุมคำถามของผู้ใช้และความเสี่ยงที่เกี่ยวข้อง หากพบ allergen นอก vocabulary ใน strict mode ระบบจะไม่ยืนยันชุดแม้เมนูอื่นถูกตั้ง confirmed แล้ว ต้องปรับ mapping จากหลักฐานก่อนใช้

แหล่งเกณฑ์ที่ผู้ใช้ให้: [อย. P450.pdf](https://food.fda.moph.go.th/media.php?id=654869394207416320&name=P450.pdf)

การ import ซ้ำจะ replace catalog ไม่ใช่ merge การแก้ CSV ไม่มีผลต่อ DB จน import และการแก้ DB ไม่เขียนกลับ CSV เก็บ revision ของ catalog ในทุก candidate เพื่อป้องกัน verify ผลจากข้อมูลเก่า


## การแก้ข้อมูลรอบประเมิน 1 (22 ตุลาคม 2569)

- S007 หอยเม่น: เปลี่ยนจาก molluscs เป็น echinoderm; ยังคง seafood และสถานะ unknown ไม่ใช่การยืนยันส่วนผสม
- S003 ปลาไหลย่าง และ S020 ปลาหมึกยักษ์ต้ม: ย้ายจากหมวดปลาดิบเป็นหมวดปรุงสุกตามคำบรรยาย dataset
- ทบทวน dietary_tags ของทั้ง 42 รายการจาก dataset เพื่อแยกของดิบ/สุกและวัตถุดิบ ไม่ได้ตรวจสูตรจริงกับร้าน
- Migration เปลี่ยนชื่อคอลัมน์ SQLite เดิมและเติมแท็กเฉพาะรายการที่ ID/ชื่อ/คำบรรยายตรงกับ CSV โดยคงราคาและ provenance ที่แก้ในฐานข้อมูลไว้ รายการที่ไม่ตรงคงสถานะไม่ทราบ; ข้อห้ามแบบแท็กจะปิดกั้นรายการที่ยังไม่ reviewed
- `confirmed` ต้องใช้เอกสารส่วนผสมรายเมนูจริง ตรวจสูตร/ซอส/ท็อปปิงและการปนเปื้อน พร้อม URL และวันที่โดยผู้ตรวจ ไม่ใช้เว็บความรู้ทั่วไปหรือข้อมูลทดสอบแทนหลักฐานของร้าน

## ขอบเขตเนื้อสัตว์บกในรอบแก้ไข 2

`beef` และ `chicken` เป็นข้อจำกัดเพิ่มเติมนอกทะเบียนฉลาก10กลุ่ม เช่นเดียวกับ pork การกรองการแพ้สัตว์บกใช้ `ingredient_allergens()` ซึ่งรวมแท็กแพ้เดิมกับ pork/beef/chicken จาก `dietary_tags` และส่ง raw tags ให้ Rego ตรวจเอง การรวมเพื่อระวังนี้ไม่ใช่หลักฐานยืนยันสูตร ไม่เปลี่ยน42รายการเป็นconfirmed

หน้าเว็บถามชนิดเมื่อผู้ใช้บอกไม่ชอบ/ไม่กิน/แพ้เนื้อ ก่อนบันทึกตามความสัมพันธ์ที่ผู้ใช้ระบุ Direct hard-filter alias “เนื้อ” ครอบคลุม pork/beef/chicken แต่ไม่รวมปลา/อาหารทะเล `scripts/catalog_audit.py --checklist <path.csv>` สร้างรายการหลักฐานที่ต้องเติมจากข้อมูลร้าน โดยไม่แก้catalog


## การปฏิเสธอาหารและการตรวจหลักฐานรอบติดตาม

“ไม่กิน/ไม่ทาน/งด/ห้าม + อาหาร” ถูกบังคับเข้า `hard_exclude_keywords` โดย `restrictions.py` หลังการสกัด JSON แม้โมเดลส่งเป็น `dislikes` ก็ตาม ลบคำ/alias เดียวกันจาก soft dislikes ทั้ง turn ปัจจุบันและ state เดิม “ไม่ค่อยชอบหมู” เป็น soft dislike และไม่สร้าง hard ใหม่ แต่ไม่ใช้การพูดเรื่องความชอบลบข้อห้ามเดิมโดยปริยาย คำกว้าง “เนื้อ” ยังคงให้เลือกชนิดสัตว์บกก่อน

`team_reviewed` ต้องมีเหตุผล ผู้ตรวจ และวันที่ ไม่ใช่หลักฐานที่ร้านยืนยัน โหมด strict รับเฉพาะ `confirmed` สำหรับผู้แพ้ CSV เดิมที่ไม่มีสองคอลัมน์ review จะเติมค่าว่างและ migration รักษาสถานะเดิม ไม่เปลี่ยนทั้ง 42 รายการเป็น reviewed/confirmed อัตโนมัติ ดู [แบบตรวจร้าน](RESTAURANT_VERIFICATION.md)

ราคา `confirmed` ต้องมี `source_url` ที่ชี้หลักฐานราคา/ภาพป้ายและ `checked_at` โดยทีมบันทึกชื่อสาขาไว้ในหลักฐานด้วย Importer ตรวจว่ามี metadata ไม่สามารถพิสูจน์ความจริงของหลักฐานแทนผู้ตรวจได้
